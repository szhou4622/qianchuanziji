## 每项任务

1. 核对目录、远程、未提交改动和未合并 PR，获取最新 main。
2. 从 main 建任务分支，写清任务、范围、验收与依赖；同一未合并任务继续原分支。
3. 在独立工作目录开发，隔离测试数据和凭据，不读取正式数据。
4. 逐文件检查差异，提交并推送，创建指向 main 的 PR，记录验证和恢复影响。
5. 等待真实 CI 成功、同步最新 main、解决讨论，按当前复核模式 Squash 合并。不能管理员绕过。
6. 回读 main、CI 和远端分支清理情况，明确未验证、未上线事项。

## 实际规则的目标值

经典 main 保护：必须 PR；批准人数 0；新提交撤销旧批准；必需 `ci-gate`，绑定 GitHub Actions；同步最新 main、解决讨论；管理员受约束；线性历史；禁止强推、删除；不锁分支。

只允许 Squash，自动删除已合并分支。Actions 默认只读且不能批准 PR，工作流显式 `contents: read`。密钥扫描和推送保护保持开启。合并不触发生产发布。

## 基线和恢复

导入 r31 的 395 个受版本管理文件。原始源码与协作配置分别记录。原仓库与来源源码完整 Git 历史在本机审计目录保存并验证为 bundle；未把其他仓库未审计历史批量发布到公开仓库。

旧 main 提交保留正常 Git 历史，旧 commercial-v1 分支在本地完整备份后清除远端入口。本次替换当前代码，不擦除历史、不删除仓库、不修改生产服务。回退用新分支和回退 PR；数据恢复与部署回退单独处理。

## 检查边界

- `repository-checks`：协作文件、来源摘要、运行数据/秘密文件、体积和冲突标记。
- `desktop-tests`：Windows / Python 3.12 完整隔离 unittest，阻断外网。
- `frontend-build`：Node 22、npm 锁定依赖、TypeScript 与 Vite 构建。
- `php-lint`：所有受版本管理 PHP 文件语法，不执行请求。
- `ci-gate`：四项必须 success，不接受 skipped/cancelled/failure。

不代替授权后桌面人工操作、真实账户投放、完整安装包构建或生产验收。本任务不重新发布产品。
