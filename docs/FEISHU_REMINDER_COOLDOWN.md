# 飞书卡片提醒冷却

停投、追投、追加预算确认卡被拒绝或过期后，同一提醒默认冷却 **60 分钟**。冷却结束后，下次规则检查仍命中才会创建新卡。规则默认每 5 分钟检查，原卡片有效期仍为 30 分钟。

适用于当前桌面默认的本地飞书长连接（`local_ws`）链路；旧 `cloud_http` 服务端链路没有在本次改动中增加冷却。

## 配置

沿用当前工具账号的本地飞书配置，新增可选字段 `reminder_cooldown_minutes`：

| 值 | 行为 |
|---|---|
| 不配置 | 60 分钟 |
| 1–10080 的整数 | 冷却对应分钟数，最长 7 天 |
| 0 | 关闭提醒冷却，恢复原提醒行为 |

配置保存在应用当前数据目录的 `feishu_local_profiles.json`，位于 `profiles.<当前工具账号>.reminder_cooldown_minutes`。不要替换整个文件或修改其他账号、群、绑定与加密凭据。手动编辑时先退出程序，只增加或修改这一字段，保存为 UTF-8 后重开程序。下面仅示意字段位置，不是可覆盖整个配置文件的模板：

```json
{
  "profiles": {
    "你的工具账号": {
      "reminder_cooldown_minutes": 60
    }
  }
}
```

集成方也可通过现有 `saveLocalFeishuConfig(config)` 接口随完整的当前飞书配置提交该字段，`getLocalFeishuStatus().profile` 返回实际生效值。界面布局和控件保持原样；现有页面保存开关时未传此字段，会保留已配置的冷却值。非法值保存失败且不改变其他配置；手工写坏的字段按默认 60 分钟读取。

配置按工具账号隔离，后续检查读取当前值。改长/改短/关闭立即作用于后续检查，不修改已有历史记录；打开冷却不会撤回已经创建的有效卡片。

## 冷却范围与计时

- 追投：同一工具账号、千川账户、计划、监控目标和策略。新的候选素材或指标波动不会绕过本轮冷却。
- 追加预算：在以上范围内再按调控任务隔离，与新建追投分别计时。
- 停投：同一千川账户、计划、调控任务、调控周期和停投动作。多个策略命中同一停投对象会共享拒绝决定；恢复后的新调控周期正常提醒。
- 拒绝从实际拒绝时间起算；过期从卡片原定到期时间起算。休眠后才处理过期不会额外等待一轮，重复检查、发卡重试、重启也不会刷新期限。

冷却依赖现有持久化任务历史，无新增数据库表或破坏性迁移，已有拒绝/过期历史同样有效。不要通过清空任务历史解除冷却；需要恢复原行为时配置为 0。

冷却期间不生成新任务、不排入新发件箱、不消耗执行限额；返回 `success=true, duplicate=true, suppressed=true`，`data.delivery_state=cooldown` 并带到期时间。现有有效卡仍按原逻辑去重和处理。自动执行、已确认任务、结果通知、日报、手动测试/预览卡以及其他账户和计划不受此提醒冷却影响。

本功能只控制重复提醒，不自动确认、拒绝或调整任何投放任务。合并源码不发布生产版本。
